== 화면 구성

[mermaid]
----
flowchart LR
    Sidebar["이름이 보이는 좌측 탐색"] --> Documents["문서 탭 · 편집기 유지"]
    Sidebar --> Review["검토 탭 · 입력과 결과 유지"]
    Sidebar --> Settings["통합 설정 · 카테고리 탐색"]
    Sidebar --> Help["검색 가능한 도움말 탭"]
    Review -->|출처 선택| Documents
    Documents --> Inspector["문서 정보 · 목차 / 관계 / 진단"]
    Settings --> Extensions["기본 확장 · 설치한 확장"]
----

좌측 탐색은 기본 280px, 조절 범위 240–420px이다. 파일·검색·즐겨찾기를 하나의 탐색 영역으로 통합하고 그래프·관계, 접을 수 있는 검토 목록, 복구 사본, 설정, 도움말을 배치한다. 작업 공간 이름은 폴더 열기·생성·닫기·최근 목록을 제공한다.

900px 이하에서는 상단의 `탐색` 버튼으로 같은 사이드바를 임시 표시한다. 넓은 창의 패널 표시·너비는 유지한다. 탐색 뒤로·앞으로와 `문서 정보`는 중앙 상단에 둔다.

== 설정과 대화상자

[cols="1,3",options="header"]
|===
|영역 |동작
|화면과 배치 |좌우 패널 표시·너비
|글꼴과 편집기 |UI·문서 글꼴과 크기, 접힌 고급 font-family 입력
|미리보기 |기본·다크·세피아 테마, 사용자 CSS 연결·적용·다시 읽기
|확장 |기본·외부 확장 설치·활성화·제거, 본문 안의 제거 확인
|외부 도구 |외부 편집기 선택, 확장 연결 관리 진입점
|===

설정은 80vw × 80dvh이며, 너비 1000px 또는 높이 700px 미만에서는 사방 16px 여백을 사용한다. 카테고리 탐색 너비는 220px이다. 650px 이하에서는 목록과 상세 화면을 전환한다. 검색은 여러 단어로 항목명·설명·카테고리를 찾고 해당 항목으로 포커스를 이동한다.

화면·글꼴·테마는 즉시 반영한다. 저장 실패는 현재 창에만 적용되었음을 알리며, 직전 변경을 되돌릴 수 있다. 기본값 복원은 현재 카테고리만 대상으로 하며 외부 연결과 확장 설치 상태는 변경하지 않는다. 미리보기 초기화는 사용자 CSS 적용을 끄되 파일 연결을 유지한다.

`DialogShell`은 헤더, 본문 스크롤 영역, 하단 행동을 분리한다. 닫기는 우측 상단과 우측 하단에 있으며 Escape와 같은 정책을 따른다. 배경 클릭으로 닫지 않는다. 본문이 길어져도 헤더와 하단은 유지한다. 짧은 입력은 최대 480px, 명령 팔레트·빠른 열기는 최대 720px를 사용한다.

취소·실행은 오른쪽, 기본값 복원·제거 같은 별도 행동은 왼쪽 또는 해당 항목에 둔다. 충돌·파일 변경 검토는 취소에 초기 포커스를 둔다. 한글 조합 중 Escape는 창을 닫지 않는다. 취소할 수 없는 작업 중에는 닫기를 비활성화하고 이유를 표시한다.

== 탭과 비동기 작업

[mermaid]
----
stateDiagram-v2
    [*] --> 표시: 기능 실행
    표시 --> 숨김: 다른 탭 선택
    숨김 --> 표시: 기존 탭 재선택
    표시 --> 종료: 닫기
    숨김 --> 종료: 탭 닫기
    종료 --> [*]
    note right of 숨김
        입력 · 결과 · 스크롤 유지
        관계 갱신과 Agent 진행 조회 중지
    end note
    note right of 종료
        해당 탭 요청만 취소
        문서 저장과 별도
    end note
----

`WorkspaceTab`은 문서와 도구를 구분한다. 같은 도구를 실행하면 기존 탭을 활성화하며 의미 비교·제안은 문서 경로별로 구분한다. 문서 편집기는 검토 탭 전환으로 다시 생성하지 않는다. Git·복구는 목록–상세, 의미 비교는 이전–이후, 제안은 변경 목록–선택 내용으로 배치한다.

[mermaid]
----
sequenceDiagram
    participant A as 검토 탭 A
    participant C as ReviewOperations
    participant B as 검토 탭 B
    participant H as 기존 IPC 호스트
    A->>C: 요청 시작
    C->>H: 소유자와 함께 단일 실행
    B->>C: 충돌하는 작업 요청
    C-->>B: 진행 위치 안내
    B->>C: 유휴 탭 닫기
    Note over C,H: A의 요청은 유지
    H-->>C: 결과 또는 취소 완료
    C-->>A: 현재 작업 공간의 유효한 결과
----

맥락 구성·AI 질의·의미 비교·제안 생성은 renderer의 `ReviewOperations`에서 한 번에 하나씩 실행한다. 취소 확인과 원래 요청의 종료를 모두 기다린 뒤 재실행을 허용한다. Electron contextBridge의 동결된 API를 그대로 프록시 대상으로 사용하지 않는다.

새 맥락 구성은 이전 AI 근거를 만료시키고, 기존 결과를 표시하되 재구성 전 전송을 막는다. 문서 편집 또는 관찰된 디스크 리비전 변경은 Git·제안 승인을 해제한다. 최종 반영 시 기존 IPC의 원문·리비전 검사는 계속 수행한다. 작업 공간 전환은 이전 요청의 늦은 응답을 무시한다.

레이아웃은 `metis.layout.v3.*`로 저장한다. v2·v1의 패널 선택·표시·너비를 가능한 범위에서 이관하고, 이전 키를 삭제하지 않는다. 기존 명령 ID와 확장 공개 API는 유지한다. 외부 확장의 내부 UI는 변경하지 않고 호스트의 창·스크롤 영역을 개선한다.

== 검증

[cols="1,3",options="header"]
|===
|자동 검사 |확인 범위
|typecheck · build |TypeScript 계약과 Electron 빌드
|단위 검사 |레이아웃 이관, 요청 소유권, 취소 후 잠금, 만료 맥락, 늦은 응답, 동결 API
|`ux-redesign-smoke.mjs` |설정 검색·되돌리기·범주 복원, 탭 상태, 도움말, 고정 행동 영역
|`workspace-tabs-smoke.mjs` |편집기 DOM·선택과 검토 스크롤 유지, 문서 수정 후 승인 해제, 탭 간 요청 간섭, 맥락 만료, 작업 공간 전환, 설정 저장 실패
|기존 Electron 회귀 |레이아웃·설정·Escape·Git·복구·비교·제안·확장·문서 기능
|화면 크기 |1920×1080, 1366×768, 800×600, 200% 확대. 확대 화면은 Electron capturePage로도 확인
|===

`npm run test:ux-redesign`로 새 두 검사를 실행한다. 기존 `test:integration`에도 포함한다. 검사는 `.pre04-runs` 아래 별도 프로필·작업 공간을 사용한다. 실 AI 서버의 품질 평가는 포함하지 않으며 AI 회귀는 로컬 고정 응답 서버를 사용한다.

2026-11-11 Windows 작업 트리에서 typecheck와 build, 단위 테스트 46개 모음·294개 검사, 도구 테스트 54개, Electron 회귀 40개 모음이 통과했다. Electron 수치는 단계별 실행과 수정 후 재검사의 각 모음별 최종 결과를 합산한 것이며, `test:integration` 한 번의 실행 결과는 아니다. 레이아웃 v2에서 v3로의 이관과 이전 키 보존도 확인했다.

개별 실행 로그와 화면 증거는 link:../.pre04-runs/ux-redesign-validation.json[검증 결과]에서 찾을 수 있다. 이번 검증에는 패키징된 배포본과 macOS·Linux 검사를 포함하지 않았다.

실제 사용자 비교 평가는 아직 수행하지 않았다. 초보 2명·반복 사용자 2명이 설정 찾기, 글꼴 변경·되돌리기, Git과 문서 왕복, 복구 사본 찾기, 도움말을 통한 작업을 수행하고 성공률·소요 시간·잘못된 선택·주관적 어려움을 기록해야 한다. 자동 검사 통과를 실제 사용성 개선의 측정 결과로 취급하지 않는다.
